`BilyEvent` autocompletes known events and still accepts your own event names.

```typescript
type BilyEvent = KnownBilyEvent | (string & Record<never, never>);
```

Event names are case-sensitive. Use the capitalization shown for Bily events. Create a stable snake_case application event only when no standard event describes the outcome.

## Prefer standard conversion outcomes

Choose the standard event that matches the verified outcome, not a button label. Keep a product-specific label in `bily_business_event` instead of changing the conversion name.

| Verified outcome | Preferred event |
| --- | --- |
| Authentication succeeded | `Login` |
| Registration succeeded | `CompleteRegistration` |
| Sales, demo, contact or signup-request form successfully submitted | `Lead` |
| Appointment actually booked | `Schedule` |
| Trial actually started | `StartTrial` |
| Subscription started | `Subscribe` |
| Checkout actually started | `InitiateCheckout` |
| Payment completed | `Purchase` |

Do not emit these conversions from a CTA click or a bare thank-you-page visit. Compatibility aliases such as `Sign Up`, `Trial Started` and `Subscription Started` remain accepted, but new integrations should use the preferred names above. `Demo Requested` has different legacy destination mappings; distinguish a submitted request (`Lead`) from an actual booking (`Schedule`).

For purchases, use the real stable order/action ID, numeric value and currency, and the verified product details required by the connected destination. Never invent identity, value or order data to make an event pass validation. Observe consent and check each destination's required fields and configuration.

### Destination mapping is not identical

The current destination adapters translate the same standard outcome differently:

| Bily event | Meta | TikTok | Google Ads action | Snapchat |
| --- | --- | --- | --- | --- |
| `Lead` | `Lead` | `Lead` | `Bily Submit lead form` | `SIGN_UP` |
| `CompleteRegistration` | `CompleteRegistration` | `CompleteRegistration` | `Bily Submit lead form` | `SIGN_UP` |
| `Schedule` | `Schedule` | `Schedule` | `Bily Submit lead form` | `RESERVE` |
| `StartTrial` | `StartTrial` | `StartTrial` | `Bily Submit lead form` | `START_TRIAL` |
| `Subscribe` | `Subscribe` | `Subscribe` | `Bily Subscription` | `SUBSCRIBE` |
| `Purchase` | `Purchase` | `Purchase` | `Bily Purchase` | `PURCHASE` |

This table describes mapping, not a delivery guarantee. Connected destinations still apply consent, configuration, required-field and delivery rules. Verify a Bily receipt and the destination result for the same event ID.

## Add product-specific application events

```typescript
track("workspace_created", {
  workspace_id: "workspace_456",
});
```

The SDK accepts non-empty custom strings, but ingestion is separately validated. Built-in lifecycle names such as `workspace_created` are recognized; other names must be configured in the website or store's Bily Moment catalog before they can be admitted. An unknown, unconfigured name is rejected as `UNSUPPORTED_EVENT`. A payload cannot add itself to that catalog. Keep a short event catalog and verify the actual Bily receipt. Custom ingestion also does not imply support by every ads destination; see the [custom event guide](/guides/custom-events).
