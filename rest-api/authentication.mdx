Use a Bily API key for server-to-server requests. Never embed an API key in browser JavaScript, mobile application code, a public repository, or a client-visible environment variable.

## Create a key

1. Sign in to [Bily](https://app.bily.ai).
2. Select the store this workload may access.
3. Open **Settings**.
4. Open **MCP**.
5. Under **Access key fallback**, enter a descriptive name and expiration.
6. Create the key and copy its full value immediately.

Bily shows the full key once. Store it in your deployment platform's secret manager. The key carries the selected store and its organization as its default API scope.

<Warning>
  Replace an older settings-generated fallback key that was created without store scope. Select the intended store, create a new key, update the workload, and revoke the older key after the replacement passes a read-only `GET /context` check.
</Warning>

<Tip>
  Use one key per environment and workload. Names such as `reporting-production` and `catalog-sync-staging` make rotation and audit review easier.
</Tip>

## Send the key

The recommended header is `x-api-key`:

```bash
curl --request GET \
  --url https://app.bily.ai/api/customer/v1/context \
  --header "x-api-key: $BILY_API_KEY"
```

Bearer authentication is also accepted:

```http
Authorization: Bearer <BILY_API_KEY>
```

Send one authentication method per request.

## Protect and rotate keys

- Keep keys only in server-side secret storage.
- Do not log request headers that may contain a key.
- Set an expiration that matches the workload's lifecycle.
- Create a replacement before revoking a production key.
- Revoke a key immediately if it may have been exposed.

## Permission failures

Keys created in Bily include the permissions available through the stable customer API and the selected store and organization scope. Requests for another store or organization are rejected. An action can also return `403` when the caller lacks its required permission.

Treat `401` as a missing, expired, revoked, or invalid key. Treat `403` as an authenticated request that is not allowed to access the requested operation or scope. If the error says the key must be reissued with a store scope, regenerate it after selecting the intended store.
