## Products and developer surfaces

<AccordionGroup>
  <Accordion title="Bily">
    The programmable customer data and activation layer for websites. Bily connects browser, server, and AI workflows around the same website, organization, and store context.
  </Accordion>
  <Accordion title="Bily Apps">
    The installable capability layer of Bily. Teams can review, configure, install, observe, update, or revoke a Bily App through the website connection they already govern.
  </Accordion>
  <Accordion title="Bily JavaScript SDK">
    The `@bilyai/js` browser package. It installs the exact Bily script URL, queues early calls, sends known or custom events, and exports browser-safe TypeScript methods and types.
  </Accordion>
  <Accordion title="Bily API">
    The versioned HTTP interface for trusted server workflows. It exposes Bily identity, stores, analytics, connected data, and supported actions through authenticated endpoints.
  </Accordion>
  <Accordion title="Bily MCP">
    The Streamable HTTP interface for compatible AI clients. It exposes two stable tools, `search` and `execute`, for current Bily operations.
  </Accordion>
</AccordionGroup>

## Events and payloads

<AccordionGroup>
  <Accordion title="Event">
    A named outcome sent from the browser with an optional payload. Examples include `PageView`, `Product Viewed`, `Order Completed`, and `workspace_created`.
  </Accordion>
  <Accordion title="Known event">
    An event name included in `KnownBilyEvent`. Known names receive TypeScript autocomplete, while the SDK continues to accept custom non-empty strings.
  </Accordion>
  <Accordion title="Custom event">
    An application-specific event name supplied by your code. Use stable snake_case names and keep changing values in the payload.
  </Accordion>
  <Accordion title="Payload">
    The optional object passed to `track()`. It can contain typed client, product, order, page, and search fields plus reviewed custom properties.
  </Accordion>
  <Accordion title="event_id">
    The identifier for one logical event outcome. The SDK generates one when it is missing. It supports correlation but is not an ingestion receipt or exactly-once guarantee.
  </Accordion>
  <Accordion title="ts">
    The event timestamp. The SDK generates an ISO timestamp when `ts` is not already provided as a string.
  </Accordion>
  <Accordion title="PageView">
    The current Bily page-view event name. The browser script records the initial document automatically; single-page applications send it explicitly for later committed routes.
  </Accordion>
  <Accordion title="Single-page application (SPA)">
    A browser application that can change routes without loading a new document. Bily needs an explicit later `PageView` from the router integration for those route changes.
  </Accordion>
  <Accordion title="Product">
    A `BilyProduct` with required `id`, `name`, `price`, and `currency`, plus optional quantity, SKU, category, brand, and image.
  </Accordion>
  <Accordion title="Order">
    A `BilyOrder` representing one order and its optional products, currency, total, tax, discount, discount code, and shipping fees.
  </Accordion>
</AccordionGroup>

## Identity and acquisition context

<AccordionGroup>
  <Accordion title="Bily browser tracking ID">
    The browser-context identifier returned by `getBilyTrackingId()`. It can persist in browser storage and is not an authenticated account ID or authorization value.
  </Accordion>
  <Accordion title="client.userId">
    Your stable authenticated customer or account ID attached to an event. It is event context, not a login command or proof of authorization.
  </Accordion>
  <Accordion title="sourceUrl">
    The current page URL supplied for an explicit event, especially an SPA page view.
  </Accordion>
  <Accordion title="referrer">
    An optional referring URL supplied with an event when your privacy policy permits it.
  </Accordion>
  <Accordion title="Attribution">
    The association between observed customer activity and acquisition or advertising context. Use Bily's returned analytics fields as the reporting contract; the SDK does not define a public first-touch or last-touch rule.
  </Accordion>
</AccordionGroup>

## Analytics and connected data

<AccordionGroup>
  <Accordion title="Conversions">
    Orders in Bily advertising analytics. Use `sum(conversions)` when aggregating order volume.
  </Accordion>
  <Accordion title="People">
    Unique browser visitors in Bily advertising analytics. Use `sum(people)` as the visitor denominator only when the selected rows represent the complete traffic population for the requested grouping.
  </Accordion>
  <Accordion title="Sessions">
    Total 30-minute visits. Use `sum(sessions)` as the session denominator only when the selected rows represent the complete traffic population for the requested grouping.
  </Accordion>
  <Accordion title="Pageviews">
    Tracked page-view events. Pageviews are event volume, not unique visitors or sessions.
  </Accordion>
  <Accordion title="Conversion rate (CVR)">
    Orders divided by a complete traffic denominator. Visitor CVR is `sum(conversions) / sum(people)`; session CVR is `sum(conversions) / sum(sessions)`. Do not use orders, revenue, customers, purchase-only sessions, or conversion-filtered rows as the denominator.
  </Accordion>
  <Accordion title="Return on ad spend (ROAS)">
    Revenue divided by spend when spend is greater than zero. Bily's normalized channel and asset reports calculate this from the report's revenue and store-currency-normalized spend. Raw platform revenue and spend remain separate fields where available.
  </Accordion>
  <Accordion title="Cost per acquisition (CPA)">
    Spend divided by orders when orders are greater than zero. In Bily reports, CPA uses order volume rather than customer count.
  </Accordion>
  <Accordion title="Customer acquisition cost (CAC)">
    Spend divided by customers when customer count is greater than zero. CAC and CPA differ whenever one customer places more than one order.
  </Accordion>
  <Accordion title="Customer lifetime value (LTV)">
    A customer's total lifetime revenue in the `customer_ltv` dataset. Average LTV is the average of customer `total_revenue`; net LTV subtracts customer refunds where that data is available. This is lifetime customer data, not period new-versus-returning revenue.
  </Accordion>
  <Accordion title="Platform money">
    Raw fields such as `p_spend` remain in the ad account's native `p_currency`. Group raw money aggregates by `p_currency`. Use normalized channel or asset reports when you need store-currency spend and efficiency metrics across accounts.
  </Accordion>
  <Accordion title="Product orders">
    Product-order occurrences in the `product_metrics` dataset. Aggregate with `sum(orders)`. A row count is not a product-order count.
  </Accordion>
  <Accordion title="Units">
    Product quantity in the `product_metrics` dataset. Aggregate with `sum(units)`. Units and product orders differ when an order contains more than one unit of a product.
  </Accordion>
  <Accordion title="Connection">
    A store-scoped link to a supported data or activation surface. Depending on the operation, Bily can expose tracking connections, catalog sync connections, connected advertising accounts, and enabled account selections.
  </Accordion>
  <Accordion title="Pixel">
    The public API resource for a store-scoped tracking connection. A pixel record has an ID, name, channel, enabled state, settings, timestamps, and optional publish state.
  </Accordion>
  <Accordion title="Ad account">
    An advertising account mapped to a Bily store. Connected accounts are available through a store's connection; enabled accounts are selected for Bily reads or supported actions.
  </Accordion>
  <Accordion title="Asset">
    A normalized campaign, ad set, or ad belonging to an enabled ad account. Asset results identify the platform, account, asset type and ID, status, budget fields when available, and the fields Bily currently supports writing.
  </Accordion>
  <Accordion title="Data readiness">
    Per-platform connector and account-selection status for a store. It tells an operator whether to connect a source, select accounts, or wait before relying on the data.
  </Accordion>
  <Accordion title="Quality warning">
    Structured analytics guidance with a code, severity, message, evidence, and recommended next step. A result marked `review_required` or carrying a blocking warning should be investigated before it drives channel, budget, creative, or attribution decisions.
  </Accordion>
</AccordionGroup>

## Access and scope

<AccordionGroup>
  <Accordion title="Organization">
    The Bily team boundary that owns access. API and MCP requests verify the authenticated identity's organization access.
  </Accordion>
  <Accordion title="Store">
    A connected commerce or web property inside an organization. Store-scoped API paths use the exact URL returned by Bily discovery.
  </Accordion>
  <Accordion title="Scope">
    The organizations, stores, permissions, and actions available to an authenticated identity or key.
  </Accordion>
  <Accordion title="Customer context">
    The authenticated Bily user plus accessible organizations and their nested stores. `GET /context` and `bily.context()` return this discovery shape in one request, filtered to the connection's allowed scope.
  </Accordion>
  <Accordion title="API key">
    A server-side credential accepted by the Bily API. A key created for a selected store carries that store and organization scope. Keep it in secret storage and never expose it in browser code, prompts, logs, or repositories.
  </Accordion>
  <Accordion title="Bily Connect">
    The recommended MCP sign-in path for compatible clients. It uses Bily's OAuth flow and the signed-in user's current organization and store memberships.
  </Accordion>
  <Accordion title="Fallback key">
    A one-time-revealed access key for MCP clients that cannot complete Bily Connect. A key created for a selected store carries that default store and organization scope in MCP.
  </Accordion>
  <Accordion title="Request ID">
    A safe correlation value returned in the Bily API `x-request-id` response header. Preserve it when diagnosing an API failure.
  </Accordion>
</AccordionGroup>

## MCP terms

<AccordionGroup>
  <Accordion title="Operation catalog">
    The current set of Bily reads and actions discoverable through MCP `search`. It includes helper signatures, schemas, and planning guidance.
  </Accordion>
  <Accordion title="search">
    The MCP tool that matches an intent to current Bily operations. It accepts `query`, optional `storeUrl`, and an optional limit from 1 to 20.
  </Accordion>
  <Accordion title="execute">
    The MCP tool that runs a focused async arrow function with `bily.*` helpers. It returns a JSON-serializable `result` and captured `logs`.
  </Accordion>
  <Accordion title="Risk tier">
    Advisory MCP planning metadata such as `read`, `draft_write`, `spend_affecting`, or `destructive`.
  </Accordion>
  <Accordion title="Approval policy">
    Advisory MCP planning metadata describing the recommended review before a write or spend-affecting action. The client approval prompt remains the visible approval boundary.
  </Accordion>
</AccordionGroup>
